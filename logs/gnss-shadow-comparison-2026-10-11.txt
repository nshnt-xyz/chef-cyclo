GNSS RAM-shadow comparison, 2026-10-11

Scope: compare fresh-boot idle activity with a GNSS lease that achieves a
fix. Original EFS/persist partitions remain read-only; no shadow save or
restore, assistance injection, firmware replacement or installation.
Raw snapshots and the host capture/analysis scripts are retained locally
at ~/chef-cyclo-evidence/gnss-shadow-20261011/. No positions were captured
by the snapshot commands or included in this report.

Method
------
Used the installed image over key-authenticated Wi-Fi SSH. Initial boot
was already fresh with GPS OFF, NMEA=0 and bringups=0. Subsequently used
two ordinary, orderly reboots of the installed image. Each snapshot
records uptime, boot id, manager status, gps-up.log length and contents,
and per-partition kernel block statistics. Sampling is about every 15 s;
event times below are observation bounds, not exact event timestamps.
The existing RMTFS binary flushes verbose output immediately.

Installed helper hashes (same on fix and final idle boot):

RMTFS launch: rmtfs -P -r -S a -v.
Caller 0 = /boot/modem_fs1 = modemst1.

Assistance / query caveats
-------------------------
Before the fix lease a separate LOC client queried predicted-orbits
validity: 2026-10-04T11:00:00Z plus 168 hours (ends October 11 11:00 UTC,
before this test). This is the modem's validity report, not independent
validation of the data or evidence that all assistance was absent.
An additional separate --loc-get-gnss-sv-info query during acquisition
timed out. Neither query reused the manager's streaming CID. The fix run
therefore differs from idle controls in both GNSS activity and these LOC
queries; this is not strict attribution to GNSS alone.

Interpretation / next step
--------------------------
The first full modemst1 write does not require a GNSS session: both idle
controls reproduced it at similar boot ages. Two additional full-image
writes occurred in the GNSS/query run and not in the longer idle control.
The 2026-10-06 acquisition-only run also wrote modemst2 without a fix,
so that write alone does not prove that a completed fix was saved.

No payloads were captured. Whole-image transfers do not identify changed
bytes or filenames, and cannot show whether the extra writes save orbit
data, last position, modem housekeeping or other NV state. One fix run
and two idle boots do not establish causality or repeatability. No
cross-boot restoration or TTFF improvement has been tested.

Keep original EFS/persist read-only. Next useful investigation is a
repeat without auxiliary LOC queries, followed by bounded, opt-in export
of RAM shadows to our own storage for content comparison / EFS analysis.
Only after defining snapshot consistency, slot/source identity, recovery
and missing-storage behavior should saved-shadow restore be evaluated
with controlled assistance and signal conditions. Direct partition
writes are not justified by this trace.

Final device state: installed image, GPS OFF with zero sessions on the
last idle boot; original partitions unchanged according to sampled block
write counters. No persistent GNSS state implementation was added.
