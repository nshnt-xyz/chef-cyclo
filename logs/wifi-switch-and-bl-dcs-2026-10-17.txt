Wi-Fi switch persistence and last-close backlight DCS, 2026-10-17

Two items left open by the idle task (docs/next-steps, 2026-10-17); the user asked to fix them the same day. Evidence (outside the repository):
wifi-bldcs-20261017/{host,live,review} in the evidence directory. Times below are IST (UTC+5:30) unless a kmsg second is given. RAM image only: nothing
installed, flashed or pushed.

1. Causes
W (the Wi-Fi switch). The switch (and nmcli radio wifi off) sets NetworkManager's WirelessEnabled. NetworkManager 1.52.2 keeps it in its state file,
default /var/lib/NetworkManager/NetworkManager.state, and /var is a tmpfs seeded from the image at every boot, so the value was lost. On the installed pair
the file read NetworkingEnabled=true WirelessEnabled=false WWANEnabled=true while the radio was off, and the next boot came up enabled.
K (last close of fb0 with the panel off). mdss_fb_release_all() on the last release ran, before blanking, whatever the power state:
  if (bl_shutdown_dcs) set_dcs_backlight(pdata, 0);  mdss_fb_set_backlight(mfd, 0);
bl_shutdown_dcs is the Motorola DT bool qcom,mdss-dsi-bl-shutdown-dcs; set_dcs_backlight is mdss_dsi_panel_dcs_bl_ctrl(), which sends DCS 0x51 and then always
msleeps 500 ms. When chef-settings had blanked the panel (FBIOBLANK POWERDOWN) and then exited or crashed, the DCS went to a powered-down DSI link: 8 exits in the
visit boot showed "mdss_dsi_cmd_dma_tx(0): wait for dma_comp timed out" for cmd 0x51 (about 0.2 s), one (TERM) also a kernel WARN in clk_branch_wait (dsi byte
clock enable -16) via mdss_fb_release_all -> mdss_dsi_panel_dcs_bl_ctrl -> mdss_dsi_cmdlist_commit -> mdss_dsi_clk_ctrl. That WARN exit was a TERM with the panel
lit: chefui blanked the panel at exit (panel_off at 10539.965) and then the DCS went to the blanked panel; the exit took 1.0 s (signal 15 at 10539.91, "screen
released" at 10540.93). An exit with the screen already off (idle-power v2 s1) took 0.71 s: exit 294.788283, timeout 294.990, released 295.494484. With the panel on at the last close (a crash with the panel lit) the DCS works as intended.

2. Fixes
DK1 (kernel, drivers/video/fbdev/msm/mdss_fb.c): the shutdown DCS is guarded with the panel power state,
  if (bl_shutdown_dcs && mdss_fb_is_power_on(mfd)) set_dcs_backlight(pdata, 0);
mdss_fb_set_backlight(mfd, 0) stays unconditional; nothing else changes and the config is unchanged. The lit case that stays is a crash or kill with the panel
lit (and a kernel shutdown with an fd still open and lit), not a TERM: chefui blanks before it closes, so a TERM exit now takes the skip path.
DW1 (initramfs/usr/bin/wifi-nm): touch /run/wifi-nm-mode, then
  state=/var/lib/NetworkManager/NetworkManager.state
  if /usr/bin/chef-state ours; then state=/data/v1/networkmanager/NetworkManager.state; fi
  exec /usr/sbin/NetworkManager --no-daemon --state-file="$state"
The state file is written by NM as a temp file plus rename in its directory, so it lives in the 0700 /data/v1/networkmanager directory (chef-storage binds only its
system-connections subdirectory). NetworkingEnabled and WWANEnabled persist with it (intended). DW2: with no file NM starts enabled; no seeding. No chef-storage
change, no settings change; the UI keeps following NM's answer. Docs: system-ui.md (Wi-Fi pages), wifi-ui.md (the wifi-nm start), storage.md (state list),
display-and-touch.md (last-close note).
