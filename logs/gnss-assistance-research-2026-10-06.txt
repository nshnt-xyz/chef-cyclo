1. Shadow semantics (local source review)

tools/rmtfs/storage.c opens the real partition read-only to populate a heap
buffer under -r. Subsequent storage_pwrite calls update that buffer, and
storage_sync is a no-op. The verbose protocol trace exposes caller, sector
address and sector count; it does not expose filenames inside modem EFS.
The installed gps-up invokes rmtfs -P -r -S a -v.

tools/tftp/{ramfs,translate,tftpserv}.c implement /readwrite as an in-process
heap table. There is no /readwrite directory on the phone to snapshot.
The initial seeds come from /usr/share/rfs/msm/mpss; named protocol WRQs
change the table. TFTP logs go to stderr immediately. RMTFS dbgprintf uses
vprintf without an explicit flush, so a regular-file stdout may delay or
split the trace. Its existing log has complete writes to modem_fs1 and
modem_fs2 (each sector 0, count 4096), but those cannot be attributed to a
specific GNSS session from this buffered trace.

4. Upstream interface research

Primary upstream sources checked on 2026-10-06:
  https://github.com/linux-mobile-broadband/libqmi/blob/main/src/qmicli/qmicli-loc.c
  https://github.com/linux-mobile-broadband/libqmi/blob/main/data/qmi-service-loc.json

qmicli exposes UTC time injection and source/validity queries. Its LOC
option list has no predicted-orbits payload upload option. libqmi defines
Inject Predicted Orbits Data (0x0035): total size, total parts, part number,
part data (schema cap 1024 bytes) and format, with a completion indication.
A future upload implementation needs these APIs and per-part completion
handling; the payload cannot simply be placed in the TFTP seed directory.
qmicli's UTC injection uses the host wall clock with 1000 ms uncertainty.
Our boot-restored clock remains unverified until chrony sync, so automatic
injection needs an explicit time-quality policy.

Qualcomm's open Android LOC adapter also starts XTRA parts at 1 and checks
each completion's status and matching part number before advancing.
Reference (older adapter, not proof of this modem's current limits):
  https://github.com/sonyxperiadev/vendor-qcom-opensource-location/blob/q-mr0/loc_api/loc_api_v02/LocApiV02.cpp#L1260

5. Next experiment (handed to implementation for diagnostic support)

Add fflush(stdout) to RMTFS dbgprintf, with no payload logging or storage
policy change. On a fresh test image, capture separate modem-startup,
idle, GNSS lease/fix, release and post-release windows, recording logfile
offsets and uptime. Watch both immediate RMTFS sector traffic and named
TFTP requests. If RMTFS changes, identify which caller/partition and
sectors; a sector trace alone still does not identify GNSS files or prove
that restoring the full EFS shadow is appropriate.

Persistence of either shadow and assistance upload remain separate future
decisions. Existing valid orbit data must be accounted for in any TTFF
comparison; this run does not establish a performance benefit.
