2. Each early finding and its regression

- Own notification sessions, not global Notifying: StartNotify once per
  connection epoch even when another client is already notifying. Only
  changes on our established sessions count. Explicit other-client test
  proves two sessions for each kind, plus reconnect session counts.
- Delayed callbacks: every pending call carries pair-attempt identity or
  sensor sid plus connection epoch, cancelled and checked before use.
  Tests cancel A, pair B while A's Connect answers late, and forget A then
  reuse its slot for B before A's delayed reconnect answers.
- Reset every kind: link, characteristic/device object and BlueZ losses
  reset all values and revolution baselines. Combo disconnect and explicit
  object-loss tests observe null for every kind; first sample after a
  reconnect has no cadence baseline.
- Durable Forget: persist the flag before BlueZ removal, wait for confirmed
  removal, then persist the record deletion before reporting forgotten.
  Failed saves retry. A blocked first save proves no RemoveDevice occurs;
  a failed/blocked final save proves no completion event occurs. Restart
  tests keep and complete pending Forget across BlueZ/daemon loss.
- HR16 and signed power: pure parsers plus daemon notifications test HR8/
  HR16, signed negative watts, power crank cadence, CSC rollovers, speed
  and cadence. The app shows signed power and each combo kind.
- CLI framing: fragmented JSON in seven-byte chunks, quoted names, list
  terminator and exact output; normal status/list/pair/forget outcomes.
- Scoped pairing agent and registration: only bluetoothd's unique sender,
  only the active device (service authorization also for saved sensors).
  It is default only during pairing, unregisters with confirmation/retries
  and re-registers normally; no default role at idle. Tests foreign bus
  callers and other devices, failed registration, failed unregistration,
  Cancel and immediate re-pair. A new attempt waits for cleanup/registration.
- Live freshness: cached Value and measurement ReadValue never count;
  notifications expire to null at five seconds. Tests stale cached values,
  stale timeout, disconnect, BT off/on and BlueZ restart.
- Storage child lifecycle: own process groups, killed at the load/save
  bound, leader exit and daemon exit. Tests hanging loaders/savers and
  descendants, newest save after a timeout and exit-save completion.
- Fresh watch values: a new watcher receives fresh power/CSC immediately,
  and no stale values are retained after source/connection loss.
- Malformed optional fields: HR energy/RR and CP balance, torque, wheel,
  crank, extremes and energy lengths validated; truncated fields rejected.
  UI JSON rejects malformed escapes/numbers/trailing data/duplicate fields,
  handles nulls and unknown types, and bounds RSSI before integer casts.

Additional live fixes: BlueZ can request security while connecting or
resolving, before StartNotify. The active attempt temporarily becomes
BlueZ's default agent and authentication errors during Connect use Pair
through that scoped agent. Tests cover that path and restoration of the
previous default role. The PC's NoInputNoOutput bluetoothctl agent still
needed an unanswered authorization prompt; --bond --central PHONE_ADDR
now gives the emulator its own agent, scoped to that phone and BlueZ.
The discoverable LE advertisement instance, with classic Discoverable off,
sets BR/EDR unsupported. Without it, an earlier dual-mode bond made BlueZ
choose BR/EDR after reboot; that rejected trial is not acceptance evidence.
