Review rounds (ui_review):
 r1: a join refused as busy tore down the running join; state changes
     before the method reply were dropped (an activation that completes
     before NM answers stayed BUSY); failed-profile Delete was
     fire-and-forget by object path; P18 was not bound to the connection
     it was opened for (Forget could delete a replacement); the Internet
     step was fixed at build.
     Fixed: join_begin refuses without touching the running join; a join
     is the returned ActiveConnection, followed by its StateChanged plus
     one Get of its State (device FAILED reasons recorded before the
     reply); profiles get our own UUID and are deleted by UUID with
     confirmation and retries; P18 keeps the profile UUID, closes when the
     connection goes or changes, Forget names that UUID; Internet step
     shown/hidden live.
 r2: getrandom could block before the pool is ready; a full delete queue
     evicted a pending delete; Delete went to the well-known name after a
     lookup, so an NM restart in between could delete another profile at a
     reused path.
     Fixed: getrandom(GRND_NONBLOCK) else /dev/urandom; delete entries are
     reserved before a new profile exists, a full queue refuses (-ENOSPC);
     Delete goes to the lookup reply's unique sender, any Delete error
     relooks up, owner changes invalidate attempts in flight.
 r3: no findings (source and host acceptance).

    the loader's 5 s bound. The bound now applies regardless; shell test.
 4. sys/gps.c kept the last fix after gps-manager went away. The view is
    now cleared on manager loss, stop and gpsd loss; test-sys covers a fix
    then gpsd loss, and a fix then manager loss.
 5. gps-manager's orderly exit did not wait for the switch save (the saver
    died with it). Now it drains the newest value for up to 3 s (logged if
    not), and a save hung for 10 s is killed so a newer one runs; shell
    tests: slow save + SIGTERM, hung save.
 6. chef-state created /data/v1/gps without syncing /data/v1. It now syncs
    the parent on every save and fails the save if that fails;
    test_chef_state: sync order and failure.
