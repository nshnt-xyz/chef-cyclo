Reboot to the bootloader without losing state, 2026-10-10
==========================================================

Spec: docs/next-steps/reboot-bootloader-handoff.md. Roles: persist_impl
(implementation), persist_review (review), persist_coord (coordination,
the user's decisions).

1. Problem

scripts/phone-boot.sh and the fastboot test and install workflow returned
to fastboot with `chef-storage shutdown --pause-init; sync; sleep 2;
btprobe restart bootloader`. btprobe's restart is a raw reboot(2)
RESTART2, so init's ::shutdown lines never ran: no chef-state shutdown,
powerd not stopped (no /data descriptor between flushes, so chef-storage's
fuser misses it). Lost each time: the pending power rows in
/run/power/log.pending, the last RTC offset save and chronyd's drift
write (logs/state-persistence-followup-2026-10-08.txt, sections 4 and 5).

2. Helper: initramfs/usr/bin/chef-reboot

`chef-reboot bootloader`, in /usr/bin of the RAM image and system_a (both
built from initramfs/; mkinitramfs.sh sets its mode). In order:
  1. lock /run/chef-reboot.lock (flock -n: a second run refuses, so it
     cannot resume init under the first); SIGHUP ignored
  2. exit trap (SIGCONT to init, kill the watchdog), INT/TERM -> exit 1,
     detached RAM-only CONT watchdog (setsid, cwd /, lock fd closed,
     150 s, above the bounded chain 1 + 8 + 100 + 20 + 2 s), then
     `kill -TSTP 1` and sleep 1 (busybox init reaps but respawns nothing
     while stopped). A refused pause is logged and the helper goes on.
  3. `timeout -k 1 5 chef-state shutdown` (as in inittab), bound 8 s
  4. plain `chef-storage shutdown` (never --pause-init: its exit trap would
     send SIGCONT before the reboot, and it returns before pausing when
     /data is not mounted), bound 100 s (its own bounds add up to ~85 s)
  5. sync, bound 20 s; sleep 2 (the caller's telnet session ends)
  6. `btprobe restart bootloader` as a child, not exec, so a returning
     btprobe still runs the exit trap: init resumed, exit 1
Each bounded step runs in the background and is polled every 0.1 s; past
its bound it gets SIGKILL and is abandoned, so a step stuck in D state
(which no timeout can kill, and BusyBox timeout execs the command in the
waited PID) does not block the reboot. Failures and overruns go to
stderr, /run/chef-reboot.log and kmsg (a missing /dev/kmsg is tolerated)
and the helper continues to the bootloader. Residual: btprobe calls
sync(2) itself before reboot(2), so a wedged eMMC can still hold it; then
only the PMIC reset (Power about 8.7 s) helps.
Without chef-state and chef-storage (stage 1, where PID 1 is the stage-1
shell) init is not paused and only sync + btprobe run; without btprobe it
does nothing and exits 1. Not added to stage 1 (mkstage1.sh): it has
neither chef tool, so it would add nothing to `btprobe restart
bootloader` there and would change the installed boot_a image.

Callers: scripts/phone-boot.sh runs `exec chef-reboot bootloader` when the
image has it and keeps the old chain as the fallback for older images
(such as the installed pair 84a0baa4 + 6062f115). Docs: live-testing.md,
features/storage.md (manual mode paragraph and loss cases),
features/battery-and-charging.md (loss cases), the 2026-10-08 log
section 4 (dated update).

3. Host tests

tools/tests/test_chef_reboot.py (bash and busybox ash, 15 cases each),
wired into `make -C tools test`: order (pause < chef-state under timeout
-k 1 5 < chef-storage shutdown without --pause-init < sync < sleep 2 <
btprobe), exactly one SIGTSTP and no SIGCONT when btprobe reboots
(stubbed as SIGKILL of the helper); bootloader reached when chef-state,
chef-storage or sync fail or hang (and all three hanging), each logged to
the log, kmsg and stderr; btprobe returning -> SIGCONT after it, exit 1;
refused pause still reaches the bootloader; TERM and INT during
chef-state -> SIGCONT, no chef-storage, no btprobe; SIGHUP ignored; lock
busy -> nothing done; lock fd closed for the watchdog, steps and btprobe
(also checked by hand: real BusyBox ash and bash leave no lock fd in a
backgrounded external command, `busybox timeout` or setsid); stage 1
without chef tools; no btprobe; usage; missing kmsg; closed stderr;
watchdog budget above the bounds; the watchdog killed on the resume
paths (round 1 review; fails 6 cases with the kill removed); callers
(phone-boot.sh order and a fastboot wait of 180 s above the helper's
131 s chain, mkinitramfs.sh mode).

make -C tools test: exit 0 on 2026-10-10, rerun after round 1 (test_chef_reboot.py: Ran 30
tests, OK; test_chef_state.py 104 OK; test_storage.py 60 OK).
