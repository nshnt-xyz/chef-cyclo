All boots were ephemeral fastboot boot. Nothing flashed. The existing ramdisk
already contains the in-progress powerd service; it was not rebuilt for this
test. New kernel boot #1 brought up USB NCM, telnet, display/touch and hci0;
one Read Local Name command (0x0c14) timed out after ~60 s idle and later LE
scan commands timed out. Killing btattach caused bt-up to reattach; subsequent
BLE scans returned advertisements, including after the UART suspended. The
control boot (old kernel, same ramdisk) returned the local name after 90 s
idle and scanned. New kernel boot #2 returned the local name both immediately
and after 82 s idle, and scanned; no timeouts or crash in that run. One flaky
boot is not enough to establish a source/config regression.
