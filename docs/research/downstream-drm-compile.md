# Downstream DRM compile experiment

2026-10-02: isolated compile assessment on chef's existing downstream kernel. No device access, module loading, DT/binding changes, GPU ownership changes, or image packaging by implementation/review. No scanout result is claimed. The only kernel source change is the reviewed DRM helper namespace separation described below; no further commits were made.

## Reproduce

For a clean kernel checkout, apply the reviewed compatibility patch first with `git -C kernel apply ../kernel-config/drm-helper-namespace.patch` (skip if already applied). This changes shared kernel source; baseline artifacts must be preserved. The durable repository patch file makes the uncommitted source experiment reproducible; it introduces no config, DT or body changes.

From repository root, `scripts/build-drm-experiment.sh` starts a **built-in** DRM probe by copying the verified `out/kernel/.config` into `out/kernel-drm`. It uses `scripts/env.sh` compiler/host flags with an isolated output override. It enables DRM/MSM, backlight support and real staging HDMI; disables legacy DRM DSI, early-card, SDE writeback, generic backlight and LCD class. Staging DSI remains enabled. KGSL and FB_MSM_MDSS remain built in.

Existing experiment configs are refused. `scripts/build-drm-experiment.sh --resume` checks the built-in scope and retained ownership settings, archives previous logs/config evidence, then resumes the isolated full build. `--modules` and `--resume-modules` reproduce the initial module scope; they do not claim module support. Explicit config edits before resume are recorded in resolved `config.diff` and `experiment.config`.

The script hashes baseline config, Image.gz-dtb and boot.img, checks preservation on exit (including ordinary build failures), and records compiler/source revisions, expanded build wrapper, invocation, environment and source diff snapshots. A manually interrupted build needs a manual hash check; attempt3 received one. Evidence resides in gitignored `out/kernel-drm`. No boot image is generated by this script.

## Attempts and scope changes

1. **Module defaults:** DRM=m, DRM_MSM=m. The script first stopped because the tree's diffconfig shebang requires absent `/usr/bin/python`; now it invokes python3. Manual continuation attempted the full build with the same isolated output/compiler flags. Full build exited 2: default early-card `ekms/edrm_drv.c` declares module_init plus late_initcall, producing duplicate module entry points. Kconfig also warned that selected BACKLIGHT_CLASS_DEVICE lacked BACKLIGHT_LCD_SUPPORT. Evidence: `attempt1/`.
2. **Reduced module probe:** EARLY_CARD=n, BACKLIGHT_LCD_SUPPORT=y, LCD_CLASS_DEVICE=n. Full build exited 2 at msm_drm.o: staging DSI, staging HDMI and writeback each declare module entry points in one composite object. Additionally Kbuild consumes composite -y/-objs lists, so this downstream Makefile's two `msm_drm-$(CONFIG_DRM_MSM)` lists omit main/core and SDE hardware objects when MSM=m. Evidence: `attempt2/`. No module linking/modpost/CRC closure or loadability was achieved. The proposed module Kbuild/registration/late-wait fixes were withdrawn when the coordinator selected built-in integration.
3. **First built-in probe:** interrupted after coordinator found legacy DRM DSI also matches live fbdev's `qcom,mdss-dsi-ctrl`. Evidence: `attempt3-interrupted/`. This attempt is not a compile result.
4. **Built-in with legacy DSI and optional HDMI/WB disabled:** failed sde_kms.c references to sde_hdmi_get_property and sde_hdmi_pre_kickoff; existing HDMI-disabled headers lack declarations. Evidence: `attempt4/`. No fabricated stubs were added.
5. **Built-in with real SDE_HDMI=y, legacy DSI=n, WB=n:** compiled DRM core objects but failed at drivers/built-in.o due duplicate DRM/fbdev IO helpers and legacy HDMI DDC functions/exports. Evidence: `attempt5/`.
6. **Same built-in config plus reviewed DRM namespace separation:** full build exited 0, including vmlinux link, MODPOST vmlinux.o, MODPOST of nine retained baseline modules, and Image.gz-dtb generation. No modpost unresolved-symbol diagnostics were found. Result recorded in root `build.log`, resolved config in `experiment.config`, full diff in `config.diff`, source/compiler/build command in `invocation.txt`.

Coordinator authorized and display-review approved explicit namespace separation in DRM files and `include/linux/sde_io_util.h`: dss register helpers become sde_dss_reg_*, msm_dss_* helpers become sde_dss_*, and DRM hdmi_ddc_read/write become msm_drm_hdmi_ddc_read/write. Declarations, definitions, callers and exports change together. Exact reverse-identifier mapping reproduces the original files, confirming no function-body/type changes. No drivers/video or fbdev headers changed and no helper implementation/ABI was substituted. The durable patch is `kernel-config/drm-helper-namespace.patch`. Patch and token map evidence are also retained in `out/kernel-drm/namespace.patch` and `namespace-symbols.txt`; full shared-source diff is in `kernel-source.diff`. Future builds from this shared tree include the renamed DRM API; protected baseline outputs remain unchanged.

Final built-in symbol inventory (`builtin-symbols.txt`) confirms main DRM registration/probe, SDE KMS, staging DSI/HDMI registration and separate DRM/fbdev helper definitions in vmlinux. `artifact-hashes.txt` records config, vmlinux, Module.symvers and isolated Image.gz-dtb hashes. The final Image.gz-dtb SHA256 is `3b0d04deb2b8a114f862d97a04643e761be44c3f9793b7f33bfb428f640a00a3`. This is successful built-in compile/link closure; DRM modules remain unsupported by the tested module configs. External WLAN is outside the kernel full-build module closure: the coordinator found 208/425 imported CRC mismatches (including module_layout) in existing WLAN against this experiment and subsequently rebuilt matching WLAN separately. Do not reuse baseline WLAN binaries with the experiment.

Legacy DSI's existing disabled-path registration/modeset stubs remain in use. Restoring real staging HDMI expands compiled driver scope and requires the coordinator's binding audit. Built-in integration is a different milestone from module closure.

## Preservation and limits

Baseline hashes are config `d2ccc3dc68ceb6e350b572d82c09e2d22f478ea871646002def954fff55c024d`, Image.gz-dtb `ddea5396a36417c9c2f34ea108cd754b72f9be09c63d35e170aba7c7c8ee7164`, boot.img `18687a1209077c45a92c67c66d8c057dafe5a139f05e73193d0ce8b9f5fd7ad5`. Preservation checks are in `preservation-after.txt` and attempt snapshots. `kernel-source.diff` contains only the reviewed namespace patch.

Hardware suitability and exact DT driver-binding audit are coordinator-owned. Do not infer no binding from main msm aliases alone: staging HDMI/DSI, unconditional legacy HDMI/eDP and msm_smmu registrations must all be checked. A successful build would not establish compatibility with chef's SDE3.2 display or 14nm PHY, native scanout, acceleration, touch/display lifecycle, or safe boot. Packaging/boot belongs to the coordinator after that audit.

Coordinator subsequently rebuilt matching WLAN and attempted two temporary boots. Both failed to reach the USB shell; baseline was restored. See [runtime probe record](drm-bringup.md#temporary-built-in-boot-probe-failed-to-reach-usb-shell). Compile closure does not imply runtime closure.

October 3 isolation also compiled exact-baseline control and DRM-core-only configurations. The control temporarily booted successfully; core-only failed to reach USB shell. See [follow-up isolation and runtime evidence](drm-bringup.md#october-3-control-build-and-drm-core-isolation). MSM hardware driver enablement is not required to reproduce that observation.

Later October 3 tests successfully booted both DRM core and the full built-in DRM configuration by reencoding unchanged userspace to smaller LZMA ramdisks. DRM initialization was observed, with no DRM card or scanout. See the [loader budget investigation and live evidence](chef-loader-kernel-budget.md). This supersedes the earlier failed runtime acceptance while preserving its historical observations; native hardware enablement remains outstanding.
